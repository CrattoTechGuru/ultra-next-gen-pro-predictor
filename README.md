# CRATTO CTRL v15.0 — Production Foundation

CRATTO CTRL is a football analytics and prediction platform. It provides statistical estimates, model diagnostics, strategy generation, historical evaluation, accounts, and shareable CRATTO slip codes.

## v15 additions
- Optional PostgreSQL persistence for accounts, sessions, and slips.
- JSON-file fallback remains available for local/testing deployments when `DATABASE_URL` is not set.
- Passwords are stored as scrypt hashes, never plaintext.
- Account sessions can be stored durably in PostgreSQL.
- Shareable `CCTRL-XXXXXXXX` slip codes persist in PostgreSQL when configured.
- Admin summary endpoint protected by `ADMIN_KEY`.
- Existing football-data.org integration and model store retained.

## Render environment variables
Set these in Render, not in GitHub:

- `FOOTBALL_DATA_API_KEY`
- `DATABASE_URL` (recommended for production)
- `DATABASE_SSL=true` unless your database requires otherwise
- `ADMIN_KEY`
- `NODE_ENV=production`

Render recommends environment variables for secrets and database connection strings. Do not commit `.env` files. https://render.com/docs/configure-environment-variables

## Database
You can use Render Postgres or another PostgreSQL provider. Render documents creating and connecting a PostgreSQL database here:
https://render.com/docs/postgresql-creating-connecting

If using a new PostgreSQL database, the application automatically creates its required account/session/slip tables at startup. `schema.sql` is also included for inspection/manual setup.

## Authentication
The application currently supports email/password registration and login. Production deployments should use HTTPS, a durable database, strong admin secrets, and rate limiting before public launch.

Supabase is also a valid future authentication/database option; its Auth system supports password, magic-link, OTP, social login and JWT-based authorization. https://supabase.com/docs/guides/auth

## CRATTO slip codes
A CRATTO code is a platform share code for a saved prediction slip. It is **not** a bookmaker-issued bet code and cannot place a wager by itself. Actual bookmaker account access or bookmaker-issued bet codes require an official bookmaker integration.

## Start

```bash
npm install
npm start
```

The server listens on `0.0.0.0:$PORT` in production.


## V16 production layer
- PostgreSQL-backed accounts, sessions and slips when `DATABASE_URL` is configured.
- CRATTO share codes.
- Betway-ready and Hollywoodbets-ready slip previews. Official bookmaker booking codes are generated by the bookmaker, not fabricated by CRATTO CTRL.
- Admin endpoints protected by `X-Admin-Key`.
- Keep `DATABASE_URL`, `FOOTBALL_DATA_API_KEY`, and `ADMIN_KEY` in Render environment variables; do not commit secrets.

## V17-V20 production layers

- V17 Operations: scheduled provider synchronization and prediction refresh orchestration.
- V18 Model Lab: model registry, version tracking, evaluation runs and calibration snapshots.
- V19 User Operations: notification preferences, audit events and user-facing activity history.
- V20 Security/Platform: API rate limiting, usage telemetry, bookmaker-ready export payloads and platform status.

Official bookmaker booking codes are never fabricated by CRATTO CTRL. Betway/Hollywoodbets must generate their own official codes through their own systems.


## V50 Master Release
V50 is the consolidated CRATTO CTRL platform build. It combines the existing authentication, PostgreSQL persistence, football-data integration, prediction engine, strategy generation, backtesting, model evaluation, calibration, Elo/team-strength analysis, portfolio/risk simulation, slip generation, bookmaker-ready exports, notifications, operations, model registry, admin/platform controls, PWA support, and the new Master Console.

### Production notes
- Set `FOOTBALL_DATA_API_KEY` in Render; never expose the key in frontend code.
- Set `DATABASE_URL` to the existing Render PostgreSQL connection.
- Use `NODE_ENV=production`.
- Configure `ADMIN_KEY` for protected administrative operations.
- Prediction probabilities are estimates and must not be presented as guaranteed accuracy or returns.
- CRATTO share codes are application-generated; official bookmaker codes must be generated by the relevant bookmaker.
- Provider freshness and available competitions depend on the football-data.org plan.

### V50 release scope
The objective of V50 is feature consolidation. After this build, development can focus on release testing, deployment verification, security review, data-provider configuration, monitoring, documentation, and user acceptance rather than adding another versioned feature layer.
